MAIN OBJECTIVE:
Create an Android app in Kotlin that runs a WhatsApp bot. A person sends a message to the bot on WhatsApp, searches for a YouTube video, chooses one of the returned results, then receives either the video file or audio file.

BOT BEHAVIOR:
1. User sends:
   /pesquisa search terms here

2. Bot searches YouTube and returns the first 8 normal video results.

3. Search results must NOT include:
   - playlists
   - channels
   - YouTube Shorts
   - live streams, if possible
   - premieres, if possible
   - unavailable/private/deleted videos

4. The result message should be clean and numbered:
   1. Video title
      Channel: channel name
      Duration: mm:ss
      Link: https://youtube.com/watch?v=...

   2. ...

5. User then sends:
   /v 1
   to download/send the selected result as video.

6. User sends:
   /a 1
   to download/send the selected result as audio.

7. User can send:
   /help
   and the bot must explain usage in a simple way.

8. User can send:
   /status
   and the bot should reply with the current status of their active job, if any.

9. User can send:
   /cancel
   and the bot should cancel their pending/current job if possible.

10. The bot must remember the last search results per WhatsApp user/chat, so when one user sends /v 1, it uses that user’s own search results and never another user’s search results.

YOUTUBE SEARCH REQUIREMENTS:
Use the official YouTube Data API v3 for searching.

Implement YouTubeSearchClient:
- Method:
  suspend fun searchVideos(query: String, maxResults: Int = 8): List<YouTubeVideoResult>

Search rules:
- Use search.list with:
  - part=snippet
  - q=query
  - type=video
  - maxResults higher than 8 initially, for example 15 or 20, then filter down to 8
  - safeSearch=none or moderate, configurable
  - videoEmbeddable=true if appropriate
  - videoSyndicated=true if appropriate
  - videoDuration=medium or long if the user wants to exclude Shorts strongly
- After getting candidate video IDs, call videos.list with:
  - part=contentDetails,status,snippet,liveStreamingDetails
- Filter out:
  - videos shorter than 61 seconds if treating Shorts as under 60 seconds
  - videos with vertical/shorts indicators if available
  - live broadcasts
  - private/unavailable videos
  - channels/playlists, which should already be excluded by type=video
- Return exactly up to 8 clean normal videos.
- Include duration parsed from ISO 8601 to human-readable format.
- Include title, channel, videoId, url, duration, thumbnail URL.

Do not scrape the YouTube search page. Use the API for search.

The app must be able to:

- Avoid sending files larger than WhatsApp limits.

  - if still too large, tell the user the file is too large and suggest audio instead
- Show progress in database, UI, logs, and notification.
- Delete the file automatically after successful sending if deleteFilesAfterSending=true.
- Also clean old temp files on startup.

Recommended file handling:
- Store temp downloads under app-specific cache directory.
- Never store in public Downloads unless explicitly configured.
- Use unique job folders:
  cache/bot_jobs/{jobId}/
- After send success:
  delete job folder.
- After failure:
  keep only logs/metadata, delete partial large files.

ASYNC / CONCURRENCY REQUIREMENTS:
This is very important.

The bot must support several WhatsApp users at the same time without mixing states.

Use Kotlin coroutines with structured concurrency:
- SupervisorJob for the bot runtime.
- CoroutineScope tied to the Foreground Service lifecycle.
- Use Dispatchers.IO for network/download/file operations.
- Use Mutex where needed.
- Use Channel or Flow for incoming WhatsApp messages.
- Use a queue system for download jobs.

Implement:
- DownloadQueueManager
- Configurable maxConcurrentDownloads, default 2 or 3.
- Per-chat sequential safety:
  - One user can have only one active download at a time by default, or make it configurable.
  - Different users can download concurrently.
- Global rate limiting:
  - Avoid starting too many searches/downloads at once.
- Retry with exponential backoff for temporary failures.
- Do not lose jobs if the app process is killed:
  - Persist queued/running jobs in Room.
  - On service restart, recover unfinished jobs safely.
  - Mark interrupted jobs as FAILED or QUEUED depending on state.
- Do not send the wrong file to the wrong chat.
- Each job must always keep:
  - chatId
  - original WhatsApp message id
  - selected video id
  - media type
  - output path
  - status
